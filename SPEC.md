# Техническое задание: «Чертолёт Грешник-3000»

Стихия: воздух. Версия: 1.0. Дата: 23.10.2026.
Статус: комплект для учебной реализации и приёмки.

![Чертолёт над инфернальным городом](assets/chertolet.png)

## 1. Назначение и основание разработки

Разработать программную модель одноместного шуточного воздушного транспорта.
Чертолёт выглядит как кресло с рожками, маленькими крыльями и реактивным котлом
под сиденьем. Котёл работает на условных баллах грехов пассажира: чем их больше,
тем быстрее полёт. После отпущения грехов аппарат теряет прибавку к скорости,
но сохраняет возможность лететь. Оценка реальных поступков пользователя не проводится.

Основание — университетское задание по спецификации, реализации и тестированию
объектной модели.

## 2. Термины, конструкция и границы модели

- **Уровень грехов** — целое число от 0 до 100, принадлежащее единственному пассажиру.
- **Ускорение от грехов** — игровая прибавка `boost_kmh` к скорости, измеряемая
  в км/ч. Это не физическое ускорение в м/с²; интегрирование скорости не требуется.
- **Базовая скорость** — 30 км/ч; прибавка за балл — 2 км/ч.
- **Положение** `position_km` — суммарный пройденный путь, а не координата.
- **Полёт** — логическое состояние между командами взлёта и посадки.

Крылья удерживают аппарат в воздухе даже при нуле грехов. Взлёт и посадка
мгновенны и не добавляют пути или времени. Движение возможно только в воздухе.
Отдельный класс пассажира не нужен: его уровень хранится в `Chertolet`.

## 3. Функциональные требования

Идентификаторы R01–R16 используются в тест-кейсах и матрице покрытия.

| ID | Обязательное поведение |
|---|---|
| R01 | Модуль `chertolet.py` экспортирует `Chertolet`, `ChertoletError`, `FlightStateError`. Конструктор принимает имя и уровень грехов; начальные путь и скорость — 0.0, `is_flying=False`. Объекты независимы. |
| R02 | Имя — строка; пробелы по краям удаляются через `strip()`. После удаления имя должно быть непустым. |
| R03 | `sin_level` — строго встроенный `int`, диапазон 0…100 включительно. |
| R04 | Шесть публичных свойств доступны только для чтения; присваивание вызывает `AttributeError` без изменения состояния. |
| R05 | `boost_kmh = 2.0 * sin_level` в обоих состояниях. В полёте `speed_kmh = 30.0 + boost_kmh`, на земле — 0.0. Верхняя скорость — 230 км/ч. |
| R06 | `take_off()` переводит аппарат с земли в полёт; повторный вызов в воздухе — ошибка. Путь и грехи сохраняются. |
| R07 | `land()` переводит аппарат на землю и обнуляет текущую скорость. Путь, грехи и прибавка сохраняются; посадка на земле — ошибка. |
| R08 | `move(distance_km)` в полёте возвращает `float` — время участка в часах `distance_km / speed_kmh`; прибавляет дистанцию к пути. Грехи, имя и состояние полёта сохраняются. |
| R09 | Дистанция — встроенный `int` или `float`, строго больше 0 и не больше 1 000 000 км. Булевы значения, другие типы, NaN и бесконечности запрещены. |
| R10 | На земле корректный `move()` вызывает `FlightStateError`, даже при максимальном уровне грехов. |
| R11 | `add_sins(amount)` принимает строго встроенный `int` в диапазоне 1…100. Итог `min(100, sin_level + amount)`. Изменение скорости в полёте немедленное; на земле скорость остаётся нулевой. |
| R12 | `absolve_sins()` немедленно устанавливает `sin_level=0`, `boost_kmh=0.0`. В воздухе скорость становится 30.0, на земле остаётся 0.0. Повторный вызов разрешён. Имя, путь и состояние полёта сохраняются. |
| R13 | `get_status()` возвращает новый независимый словарь ровно с шестью ключами и типами из §4.2. Старые снимки не меняются после команд, изменение снимка не влияет на аппарат. |
| R14 | Исключения и их сообщения соответствуют §6; порядок валидации детерминирован. Все неуспешные публичные команды сохраняют состояние. |
| R15 | Последовательные участки суммируют путь, включая участки после посадки. Новая скорость применяется только к следующим участкам; прежние возвращённые времена не пересчитываются. Грехи при движении не расходуются. |
| R16 | Отпущение на земле не позволяет вернуть прежнюю прибавку повторным взлётом. После отпущения можно вновь добавить грехи по общим правилам R11. |

## 4. Публичный интерфейс

### 4.1. Класс и конструктор

```python
class Chertolet:
    def __init__(self, name: str = "Грешник-3000", sin_level: int = 0) -> None: ...
```

Конструктор проверяет имя, затем уровень грехов. Допустимое имя сохраняется после
`strip()`, уровень сохраняется без преобразования типа. Создаётся аппарат на земле,
`position_km=0.0`. Все числовые входы, кроме дистанции, целочисленные.
Подклассы числовых типов, `Decimal`, `bool` и числовые строки не принимаются.

### 4.2. Свойства и снимок состояния

| Свойство / ключ снимка | Тип | Единица | Начальное значение |
|---|---|---|---|
| `name` | str | — | Нормализованное имя |
| `sin_level` | int | условный балл | Входной уровень |
| `boost_kmh` | float | км/ч | `2.0 * sin_level` |
| `speed_kmh` | float | км/ч | 0.0 |
| `position_km` | float | км | 0.0 |
| `is_flying` | bool | — | False |

`get_status()` возвращает все эти ключи без дополнительных полей. Порядок ключей
не является частью контракта. Прямое изменение внутренних полей с префиксом `_`
вне публичного контракта и не поддерживается.

### 4.3. Методы

| Сигнатура | Результат | Изменения |
|---|---|---|
| `take_off() -> None` | None | `is_flying=True`, скорость по R05 |
| `land() -> None` | None | `is_flying=False`, скорость 0.0 |
| `move(distance_km: float) -> float` | Время только данного участка, часы | Только суммарный путь |
| `add_sins(amount: int) -> None` | None | Уровень, вычисляемая прибавка и скорость |
| `absolve_sins() -> None` | None | Уровень и прибавка обнуляются, скорость пересчитывается |
| `get_status() -> dict` | Независимый снимок | Нет |

Изменение грехов разрешено и на земле, и в воздухе. Никаких отложенных команд,
таймеров, частичного движения или расхода грехов нет. Время каждого участка
рассчитывается по скорости на момент вызова. Общее время маршрута при необходимости
суммирует вызывающая сторона. Итоговый путь должен оставаться конечным;
защитная проверка выполняется до изменения пути.

## 5. Сценарии приёмки (Given / When / Then)

### 5.1. Обычный рейс — TC-S-001

**Дано:** уровень 50, аппарат на земле, путь 0.
**Когда:** взлететь, пролететь 13 км и 26 км, приземлиться.
**Тогда:** скорость в полёте 130 км/ч, времена 0.1 и 0.2 ч,
путь 39 км, грехи 50, аппарат на земле, текущая скорость 0.

### 5.2. Отпущение в воздухе — TC-S-002

**Дано:** уровень 100, аппарат взлетел, скорость 230 км/ч.
**Когда:** пролететь 23 км, отпустить грехи, пролететь ещё 3 км.
**Тогда:** оба участка занимают по 0.1 ч. После отпущения аппарат остаётся
в воздухе, грехи и прибавка равны 0, скорость 30 км/ч. Итоговый путь 26 км.

### 5.3. Повторное накопление — TC-S-003

**Дано:** полёт с нулём грехов.
**Когда:** пролететь 3 км, добавить 50 грехов, пролететь 13 км,
добавить 80 грехов, пролететь 23 км.
**Тогда:** каждый участок занимает 0.1 ч; скорости — 30, 130, 230 км/ч.
Итоговый уровень ограничен 100, путь 39 км.

### 5.4. Ошибки и продолжение — TC-S-004

**Дано:** уровень 10, аппарат взлетел, пролетел 5 км за 0.1 ч и сел.
**Когда:** вызвать на земле `move(1)`, `move(0)`, `add_sins(True)`,
перехватывая каждую ошибку; затем отпустить грехи, взлететь,
пролететь 3 км и сесть.
**Тогда:** первые три команды дают соответственно `FlightStateError`,
`ValueError`, `TypeError` и не меняют снимок. Последний участок занимает 0.1 ч;
итоговый путь 8 км, уровень 0, аппарат на земле.

### 5.5. Отпущение между рейсами — TC-S-005

**Дано:** уровень 100, завершён рейс длиной 23 км, аппарат на земле.
**Когда:** отпустить грехи, снова взлететь, пролететь 3 км.
**Тогда:** на земле после отпущения скорость и прибавка равны 0;
после взлёта скорость 30 км/ч, последний участок занимает 0.1 ч,
итоговый путь 26 км, уровень остаётся 0.

## 6. Ошибки, порядок проверок и атомарность

```text
RuntimeError
└── ChertoletError
    └── FlightStateError
```

Ошибки типов — `TypeError`, диапазонов — `ValueError`.

| Условие | Исключение | Точное сообщение |
|---|---|---|
| Имя не str | TypeError | `name must be a string` |
| Имя пусто после strip | ValueError | `name must not be blank` |
| Уровень не int, включая bool | TypeError | `sin_level must be an integer` |
| Уровень вне 0…100 | ValueError | `sin_level must be between 0 and 100` |
| amount не int, включая bool | TypeError | `amount must be an integer` |
| amount вне 1…100 | ValueError | `amount must be between 1 and 100` |
| Дистанция не int/float, включая bool | TypeError | `distance_km must be a number` |
| Дистанция ≤ 0, > 1 000 000, NaN или ±∞ | ValueError | `distance_km must be between 0 (exclusive) and 1000000` |
| Взлёт в полёте | FlightStateError | `already flying` |
| Посадка на земле | FlightStateError | `already on ground` |
| Движение на земле | FlightStateError | `cannot move on ground` |
| Неконечный итоговый путь | ValueError | `position_km must remain finite` |
| Присваивание публичному свойству | AttributeError | Текст зависит от Python, не фиксируется |

Порядок: конструктор — тип имени, непустота, тип уровня, диапазон уровня;
`move` — тип дистанции, диапазон, состояние полёта, конечность итогового пути;
`add_sins` — тип, диапазон, изменение. Огромный целый аргумент отклоняется
по диапазону без преобразования в float. Ошибки типов/значений дистанции
имеют приоритет над запретом движения на земле. Все проверки завершаются
до изменения состояния, поэтому ошибочная команда не имеет частичного эффекта.
Защита от переполнения накопленного пути недостижима в практически выполнимом
числе вызовов при лимите участка; специально менять приватные поля ради неё
при приёмке не требуется.

## 7. Нефункциональные требования и состав поставки

- Python 3.10 и выше; реализация использует только стандартную библиотеку.
- Тесты — pytest версии от 8 до 9 включительно; запуск `python -m pytest -q`.
- Один основной класс, простые методы, свойства для чтения, два доменных исключения.
- Нет сети, случайности, часов реального времени или интерактивного ввода.
- Файлы UTF-8: `SPEC.md`, `TEST_CASES.md`, `chertolet.py`,
  `test/test_module.py`, `test/test_scenario.py`, `README.md`,
  `requirements-dev.txt`, `pytest.ini`, `VERIFICATION.md`.
- float сравниваются в тестах через `pytest.approx` там, где выполняется деление.
  Физическая точность и точность длинных накоплений сверх обычного float не заявляются.

## 8. Вне рамок

Не моделируются физическое ускорение, высота, координаты, погода, препятствия,
топливо, энергия, повреждения, несколько пассажиров, смена пассажира,
база поступков, реальная религиозная практика, графика, API и сохранение файлов.
Образ котла и крыльев — описание конструкции; дополнительных классов для них нет.
